# 启动参数与配置关系

入口：[agv_navigation_real.launch.py](../../src/agv_bringup/launch/agv_navigation_real.launch.py)。本页对应该入口，不把仿真入口或整机启动参数混用。

## 全部入口参数

下表中的“默认”来自入口声明，“当前用法”对应已记录的完整实机命令。安装包 share/config 路径在本机 symlink-install 下通常指向源码，但应以实际安装路径核对。

| 启动参数 | 默认 | 当前用法及作用 |
| --- | --- | --- |
| `map` | 必填 | `maps/seer/20251120141209997_navigable.yaml`；设置地图服务器文件 |
| `mode` | `observe` | `execute`；观察模式只有采集/规划，执行模式增加控制链 |
| `connection` | 空 | `192.168.192.5`；传给新建的雷达、里程计、定位、保护节点 |
| `domain_id` | 环境 ROS_DOMAIN_ID，否则 216 | 当前环境设为 216；各终端一致 |
| `rviz` | `true` | 打开实机 RViz 文件 |
| `params_file` | agv_bringup/config/agv_nav2_real.yaml | 当前显式传现场 `nav2_locked_arm_site.yaml`；各 Nav2 节点共用 |
| `guard_params` | robot_move/config/navigation_guard.yaml | 保护节点和 Python 执行门禁读取 |
| `localization_params` | robot_move/config/seer_localization.yaml | 当前显式传现场 `localization_observe_site.yaml` |
| `commissioning_file` | agv_bringup/config/agv_navigation_commissioning.yaml | 现场确认、地图身份与文件哈希 |
| `lidar_params` | lidar/config/seer_lidar.yaml | 当前未显式覆盖，使用该默认 |
| `odom_params` | robot_move/config/seer_odometry_confirmed.yaml | 当前未显式覆盖，使用该默认 |
| `lidar_mounts_file` | agv_description/config/lidar_mounts.yaml | 当前未显式覆盖，使用该默认 |
| `reuse_lidar` | `true` | 当前 `false`，新建 lidar_node |
| `reuse_odometry` | `true` | 当前 `false`，新建 seer_odometry |
| `reuse_localization` | `true` | 当前 `false`，新建 seer_localization |
| `reuse_description` | `true` | 当前 `false`，新建纯描述/雷达 TF 发布者 |
| `reuse_map_server` | `false` | 当前未覆盖，因此新建 map_server |

`reuse=true` 表示依赖已有节点，不是同时再启动另一套；对应参数文件也不会自动更新已有进程。入口会检查同名节点、TF 描述发布者和部分竞争底盘通道。

## 参数覆盖顺序

1. `params_file` 同时供 map_server、planner_server 及执行插件读取；显式现场文件覆盖默认模板的选择，不是与默认模板叠加。
2. 入口在 Nav2、采集、保护等节点上显式传 `use_sim_time=false`，实机使用系统时间。现场定位 YAML 当前保存的是 `true`，在此入口下会被覆盖成 `false`；单独启动定位节点时需使用 `false`，不能照搬未覆盖的值。
3. `connection` 由入口显式传入，不依赖历史 YAML、URDF 注释或脚本中的旧 IP。
4. `map_server.yaml_filename` 由 `map` 的绝对路径设置，Python 门禁核对该路径和审核记录哈希。
5. 实机入口调用机器人描述时固定 `model=front_only`，前后雷达 TF owner 均为 `standalone`，读取挂载文件。不启动整机 ros2_control、机械臂驱动或 AMCL。
6. Nav2 在部分源码中还有默认值；明确传入 YAML 时以 YAML 为准。修改了错误的模板文件，通常不会影响当前现场命令。

## 文件之外的关键执行逻辑

| 来源 | 当前行为 |
| --- | --- |
| [navigation/node.cpp](../../src/robot_move/src/navigation/node.cpp) | 保护节点仍有 C++ 置信度下限 `0.1`，诊断字段、TF 发布者和命令时效检查 |
| [localization/node.cpp](../../src/robot_move/src/localization/node.cpp) | 未传 min_confidence 时声明默认 `0.5`；当前现场/通用 YAML 明确设 `0.1`。读取参数后不会自动跟随磁盘变化 |
| [localization/core.hpp](../../src/robot_move/include/robot_move/localization/core.hpp) | 质量门禁还检查地图、状态、数值有效性、定位跳变等 |
| [navigation/guard.cpp](../../src/robot_move/src/navigation/guard.cpp) | 普通零速为 CommandedStop，故障/运动断流仍锁定；不得用旧速度自动恢复 |
| [execution_gate.py](../../src/agv_bringup/agv_bringup_sim/execution_gate.py) | 实时输入、运行参数、控制图、心跳和生命周期检查；允许只读记录订阅者，限制额外速度发布者 |
| [real_navigation.py](../../src/agv_bringup/agv_bringup_sim/real_navigation.py) | 启动前审核、地图哈希、速度范围和配置结构检查 |

因此只改定位 YAML 不一定能绕过 C++ 下限；只改 C++ 源文件也不会让已有二进制自动更新。当前 `input_freshness_contract_verified=true` 是现场配置声明，不是程序新完成的数据新鲜度认证。
