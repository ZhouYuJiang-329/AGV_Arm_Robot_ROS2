# 仙工只读地图定位接入

目标链为 `map → odom → base_link → laser_front_link / laser_back_link`。新增入口只读取已有定位，不执行2002重定位、2003确认、DO、速度或导航命令。现有1005连续积分、断线保留累计odom、接收时间约定均不改变。不要运行会初始化底盘的整机入口来做本页只读验收。

## 已核对的代码与坐标

- `robot_move` 已有 `Client::queryPose()` 的1004解析，但只返回x/y/angle；AGV重定位流程会调用它，不是可供ROS订阅的常驻定位反馈。新增 `SeerLocalizationSource` 复用原 `Transport`，不复制socket或帧实现，不启动AGV运动策略。源层严格解析协议，`localization/core.hpp` 负责SE(2)组合及质量门控，ROS层负责时间对齐、TF、Pose和诊断。
- 本地API《查询机器人位置》：x/y米，angle弧度；confidence可缺省，范围[0,1]；loc_method=3表示里程计模式；`create_on`是**API上传时间**。没有已验证的设备定位采样时间、采样序号或协方差。confidence不转换成协方差，Pose使用 `PoseStamped`，不声称可检测设备缓存重复值。
- 本地API《查询机器人定位状态》1021：0初始化、1成功、2重定位中；旧版3完成待确认不能当成功。本节点只接受1，绝不自动确认。1004没有地图ID，地图名及可选MD5从《查询机器人信息》1000的`current_map`、`current_map_md5`读取。
- 本地《坐标系》说明世界/机器人系为右手系，差动车体原点在轮轴中心；这不能证明当前全向车API参考点与CAD一致。已有用户CAD确认记录：两原点重合，base_link相对仙工机器人坐标系旋转+π/2。新配置沿用该数值，但 `base_transform_confirmed=false` 表示1004所用实体参考点还需要现场验证；不能仅凭frame_id认定一致。参见[连续里程计接入](连续里程计接入.md)。
- [SMAP转换说明](仙工SMAP地图转换说明.md)和转换代码保留SMAP米制x/y、分辨率和轴向，YAML origin为左下角、yaw=0，只有图像行方向反转。本地图报告origin为[-9.673,-2.235,0]、分辨率0.02m，这不是要再应用一次的定位偏移。默认地图对齐为单位变换，是依据转换实现的假设，尚未独立验证地图来源、控制器原点有无修改。**不翻转世界Y、不再加YAML origin。**

约定 `T_A_B` 将B中的坐标变到A：

```
T_map_base = T_ros_map_seer_map × T_seer_map_seer_robot × T_seer_robot_base_link
T_map_odom = T_map_base × inverse(T_odom_base)
```

实现包含旋转作用下的平移耦合，不直接相减x/y/yaw。`map_{x,y}_in_ros_m / map_yaw_in_ros_rad` 表示仙工地图原点在ROS map中的位姿；`base_{x,y}_in_seer_m / base_yaw_in_seer_rad` 表示base_link原点及轴在仙工机器人系中的位姿。所有角度rad、长度m。不要用机械偏移掩盖地图对齐误差，也不要分别给odom和定位配置不一致的底盘偏移。

## 时间、质量和故障策略

每周期在同一状态连接上依次执行 `1000 → 1021 → 1004 → 1021 → 1000`，全部共享单个最长1秒截止时间。前后状态、地图名、MD5不一致则整组丢弃；这些查询不具备设备端原子快照语义，仍可能漏掉在两次检查之间完成的短暂事件。默认2Hz，慢周期跳过、不补发，失败指数退避0.5～5秒；连接仅状态端口、最长1秒。线程独占源和Transport，ROS执行器不等待网络，退出唤醒并join，实源上界约当前连接或事务剩余1秒加调度开销。

`stamp_mode=receive_time` 是本轮唯一支持模式。1004响应刚收齐即记录本机ROS/steady时间，后续质量查询不挪动时间戳。不使用create_on、未知设备数值或查询起始时间冒充采样时间。内部定位滞后和单向网络延迟未知；即使查询很快也无法证明定位很新。

ROS层订阅真实 `/tf` 中的动态`odom→base_link`，用tf2缓存查找**1004接收时刻**的变换；只接受直接、平面、有限、单位四元数的odom TF。查找前要求存在两侧样本（正好命中时可用单样本），插值间隔≤`max_odom_bracket_sec`，最新odom年龄≤`max_odom_age_sec`，总查询延迟≤`max_query_latency_sec`，样本ROS/steady年龄≤`max_sample_age_sec`。TF尚未到达时异步等待，超期丢弃。TF缺失、过期、超差和时钟回退均报告诊断；时钟回退清理TF时间缓存及待处理样本，**不清零odom**。

`/seer/localization/base_pose`始终带原接收时间戳，每个新接受查询只发布一次。
`tf_publish_mode=measurement_time`保留Pose/TF同戳单次发布的兼容模式；实机YAML现明确选择`bounded_odom_hold`：
在原定位和最新odom均新鲜时，以已接受校正和新收到的odom提供map→odom支持，时间戳只取收到的odom时间、严格递增且不在未来。
这是有界odom推算，不是新绝对定位观测；诊断`response_age_sec`仍追溯原接受Pose，不能由TF或定时器续期。断线、过期、质量错误停止支持。
正常等待新样本的odom插值通过`pending_reason`单独报告，不再覆盖尚有效的接受样本；真正过期和故障仍失效。
完整原理、回归与实机结果见[定位诊断与TF时间接入修复](定位诊断与TF时间接入修复_2026-11-12.md)。

默认要求confidence存在且≥0.5，拒绝loc_method=3。loc_method缺省时无法排除设备的特殊定位模式；若confidence缺省，只能在明确接受该限制后配置`require_confidence=false`。这些是工程筛选阈值，没有实机精度标定依据。

`expected_map` 必须明确填写API1000返回的地图名；`expected_map_md5`可额外锁定控制器地图版本，不能未经验证拿原SMAP文件MD5等同于厂商MD5。首次质量合格时还锁定观测到的MD5，运行中同名地图内容变化会拒绝更新，需检查地图后重启。地图名不匹配不自动采用，不自动加载另一张ROS地图。MD5缺失时无法可靠识别同名内容被替换；缺地图名则查询失败。切回预期名和原MD5可恢复。

合理校正与异常跳变按**map→odom校正量的变化**判断，避免把机器人正常移动当作跳变。变化超过0.5m或0.5rad先隔离；连续3个新查询的候选校正在0.1m/0.1rad内稳定后接受，诊断`persistent_correction_accepted`，可以响应控制器人工重定位后的新结果。配置`jump_recovery_samples=0`可禁用自动接受大校正，人工检查后重启。稳定错误也可能通过此启发式，不能据此证明定位正确；无设备采样序号，3个新响应不一定是3次设备采样。失效、地图错误、通信失败会清理候选计数，但保留上次校正供后续比较；任何时候都不发布单位变换冒充有效定位。

启动入口不含AMCL、slam_toolbox、Nav2导航或控制节点。节点监听`/tf`、`/tf_static`，发现其他发布者给`odom`设置父坐标系后锁定停发，需移除冲突再重启；通过DDS发布者GID排除自己的TF。首次发布前留1秒发现期。分布式发现无法从数学上保证从未短暂重叠，实机仍必须检查发布者；不要同时启动第二份本节点、AMCL、slam_toolbox或静态map→odom。之后接Nav2也只启动导航部分，并禁用其定位TF所有者；当前`agv_navigation.launch.py`包含Nav2完整bringup，不能与本节点直接并用。

## 构建与启动

工作区根目录，每个终端都使用相同domain；本例216，可选其他空闲域，但所有实机节点必须一致：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select robot_move lidar agv_bringup \
  --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
source install/setup.bash
export ROS_DOMAIN_ID=216
```

先只读检查地图、状态、置信度（不初始化车辆）：

```bash
ros2 run robot_move seer_localization_inspect 实际控制器IP
cp src/robot_move/config/seer_localization.yaml /tmp/seer_localization.yaml
```

编辑副本中的坐标、质量及时间阈值；确认对应物理关系后再设置两个`*_confirmed=true`。未确认仍可用于观察，但诊断始终明确标记`UNVERIFIED_ASSUMPTION`，不得当作已标定参数。按inspect结果可填写`expected_map_md5`。不要为消除报错盲目降低confidence或放宽时差。

如果odom、雷达已经运行，不重复启动。缺少时各用独立终端：

```bash
ros2 launch robot_move seer_odometry.launch.py connection:=实际控制器IP \
  params_file:="$PWD/src/robot_move/config/seer_odometry_confirmed.yaml"
ros2 launch lidar seer_lidar.launch.py connection:=实际控制器IP
```

已有安装TF时沿用。没有时，可只发布已配置的雷达挂载，不启动整机控制（不得与已有同名TF的robot_state_publisher重复）：

```bash
ros2 run robot_state_publisher robot_state_publisher --ros-args \
  -p use_sim_time:=false \
  -p robot_description:="$(xacro src/agv_description/urdf/lidar_only.urdf.xacro \
    enable_front_lidar_tf:=true enable_back_lidar_tf:=true)"
```

前雷达外参已有现场比对记录，后雷达yaw及高度仍为暂定值；见`agv_description/config/lidar_mounts.yaml`，不能把该文件注释的暂定数据标成完整标定。

启动只读定位显示（必须使用匹配的ROS地图；以下地图名为本机inspect实测值）：

```bash
ros2 launch robot_move seer_localization_view.launch.py \
  connection:=实际控制器IP expected_map:=20251120141209997 \
  params_file:=/tmp/seer_localization.yaml \
  map:="$PWD/maps/seer/20251120141209997_navigable.yaml" rviz:=true
```

此入口只启动定位、地图服务器、仅管理地图服务器的生命周期节点及可关闭的RViz；所有节点强制`use_sim_time=false`。不启动odom、雷达采集、雷达TF、机械臂或底盘驱动。若已有地图服务器，改用`ros2 run robot_move seer_localization_node --ros-args --params-file /tmp/seer_localization.yaml -p connection:=实际控制器IP -p expected_map:=实际地图名`，然后在已有RViz加载`config/seer_localization.rviz`。

## RViz只读验收

1. Fixed Frame为`map`，Map订阅`/map`且使用Transient Local；确认没有沿用仿真地图和仿真初始位姿。
2. Axes显示`base_link`，Pose显示`/seer/localization/base_pose`，前后LaserScan为`/scan_front`、`/scan_back`（Best Effort）。初始视角在原点，若机器人在屏外，用选中/聚焦或移动视角到Pose箭头位置。红X、绿Y是CAD坐标轴；本机base_link相对仙工轴旋转π/2，不能把红X直接当车头。
3. 检查`ros2 topic echo /diagnostics`，重点看定位状态、confidence、地图、年龄、查询延迟、odom插值间隔、tf_available及拒绝原因。低confidence或缺TF时不出现新Pose/TF是预期行为。`ros2 run tf2_tools view_frames`及`ros2 topic info /tf --verbose`核对唯一所有者。
4. 对照现场独立标线/卷尺，检查位置与朝向；在至少两处不同朝向检查前后雷达与墙面。分别记录平移、角度、点到墙残差及独立测量精度。仅看到机器人不算精度通过。
5. 记录至少60秒：

```bash
/usr/bin/python3 tools/record_seer_localization.py --seconds 60 \
  --output /tmp/seer_localization_session.json
ros2 bag record /odom /tf /tf_static /seer/localization/base_pose \
  /diagnostics /scan_front /scan_back
```

记录器只订阅ROS，保存每条消息接收年龄与各节点诊断；不会连接控制器、不启动其他节点、不发命令。输出文件存在会拒绝覆盖。诊断里的TF可用性指最近尝试，必须结合年龄及错误原因判断实时性。

## 离线合成数据显示

新增独立演示入口，已在本机打开RViz并看到地图与AGV模型：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select robot_move agv_bringup \
  --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
source install/setup.bash
ros2 launch agv_bringup seer_localization_demo.launch.py \
  map:="$PWD/maps/seer/20251120141209997_navigable.yaml"
```

默认domain=217、仅本机发现；可用`domain_id:=其他空闲域`指定，`rviz:=false`可关闭查看器。不要让实机或其他测试同时使用该演示域。此为使用wall clock的合成数据演示，`use_sim_time=false`；不启动Gazebo动力学、Nav2运动控制、实机采集或硬件插件。图中的仙工地图只作为视觉背景，合成路径未做碰撞检查，不能认为它是现场可通行路径。

`seer_localization_demo`从独立的编译入口注入无Transport/Client/socket的假定位源，使用正式LocalizationNode处理数据；合成连续odom为50Hz、定位响应10Hz、confidence=0.95，不能混同为实机置信度。每20秒切换一次地图校正量（0.8m及0.4rad），可观察短暂`jump_quarantined`，3次稳定响应后`persistent_correction_accepted`；地图中的模型发生校正，odom累计轨迹仍连续。

RViz Fixed Frame为map；“SYNTHETIC AGV”是现有CAD几何与零位关节预览。用滚轮缩放、Shift+鼠标中键平移、鼠标左键旋转视角；此配置没有导航目标或初始定位工具。不伪造与墙面吻合的激光扫描，实机前后雷达对齐仍按前面的独立验收操作。终端Ctrl+C结束该入口。

演示运行核对：[23秒TF记录统计](validation/seer_localization_demo_verification.json)中收到1151条odom TF、228条map→odom TF；最大相邻odom平移约0.00145m，定位校正约0.8m，并观测到隔离与稳定后接受的诊断。新增演示后3项定位回归CTest、bringup的7项既有Python测试、演示C++格式及launch的flake8/pep257通过。截图：[合成数据显示](validation/seer_localization_demo.png)。这些只验证离线显示及计算链路，不验证实机精度。
