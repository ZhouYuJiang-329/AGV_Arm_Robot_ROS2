# 导航过程记录与回看

`tools/record_navigation.py` 是只读订阅工具，不发送导航目标、速度、恢复或生命周期请求。应在发导航目标前启动；不能找回启动记录器之前的运动过程。

在工作区、新终端执行：

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
/usr/bin/python3 tools/record_navigation.py --domain-id 216
```

默认最多记录一小时，终端 Ctrl+C 可提前结束。也可指定 `--seconds 600` 记录十分钟。退出时会关闭自身的 rosbag 子进程并写完整摘要，不停止导航。输出目录为 `logs/navigation/日期_时间/`，`logs/navigation/latest.txt` 指向最近一次默认目录记录；该目录已被 Git 忽略。

## 每次记录的内容

| 文件 | 用途 |
| --- | --- |
| `summary.json` | 记录时长、收到的话题与条数、任务最终状态、路径终点、估算行程、保护状态变化和停止原因 |
| `overview.svg` | 最新全局规划路径与实际地图坐标轨迹对比；图中蓝色为规划，橙色为实际估计轨迹 |
| `trajectory.csv` | 每个轨迹点的接收时间、原 TF 时间、地图坐标和朝向，方便对照实际移动和停车 |
| `events.jsonl` | 全部收到的中间规划路径、里程计、三段速度、任务状态/反馈、诊断和 ROS 日志 |
| `bag/` | 原始扫描、TF、地图、规划路径、里程计、速度、状态、反馈等 rosbag；每五分钟分段 |
| `configuration/` | 已知现场配置、地图文件和 SHA256 快照；这是磁盘快照，不能冒充运行时参数覆盖值 |
| `rosbag.log` | rosbag 本身的运行情况；bag 提前退出也会写入摘要 |

摘要和路径图每五秒刷新，未结束时也可查看。实际轨迹取 map→base_link TF，每秒最多五点；缺失、过期或重复时间戳不编造新轨迹点。行程不计相邻点超过 0.5 米的定位跳变，并单独计数；轨迹是定位估计，不能代替现场独立测量。图最多保留两万个实际点，CSV 保留全部点。无地图 TF 或导航尚未启动时，图会显示没有轨迹；这不代表导航失败。

原始记录默认不包含体积很大的全量 costmap，扫描、地图和规划路径仍会记录；确需排查局部避障时增加 `--costmaps`。只需要轻量摘要可增加 `--no-bag`。

任务状态码：4=导航器报告成功，5=取消，6=失败。规划终点来自路径消息；如果目标直接通过动作服务发送，原始请求不一定存在于话题中。工具会尝试记录已有的动作服务 introspection 事件，但不会主动启用它；未收到原始请求时，不把规划终点当成已取得的原始请求。也不把导航器成功状态直接当成独立实测的物理到点确认。

## 后续查阅

告诉助手“查看 logs/navigation/latest.txt 对应的导航记录”，即可先看 summary.json 和 overview.svg，再按事件时间核对 events.jsonl、trajectory.csv 和 bag。

原始 bag 中包含实际速度话题。分析时优先直接读取文件；如果需要 ROS 回放，必须使用与实车隔离的域，不能在运行底盘的域 216 直接回放。

如果记录器由助手后台启动，可读取本次目录的 `recorder.pid`，只向该进程发送 SIGTERM 正常结束；正常结束后 PID 文件会移除。不要仅凭很早以前记录的 PID 操作进程。

验证：`source /opt/ros/jazzy/setup.bash && /usr/bin/python3 tools/tests/test_record_navigation.py -v`。集成测试只在隔离域 222 发布模拟 TF、规划和任务状态，不连接车辆。

## 与执行门禁兼容

门禁在专用速度话题上严格限定发布者，并要求控制链路必须存在；只读记录器可增加订阅者。早期图检查同时限制订阅者数量，会导致记录器开启后执行节点一直 unconfigured、导航动作服务不可用；已补充记录器并存的图检查与实际 Nav2 插件集成测试。升级门禁后需重启原导航启动进程才能生效，无需停止只读记录器。额外速度发布者、缺失控制链路、类型不匹配、旧底盘通道和输入过期仍被拒绝。

## 同步记录舵轮角度

需要分析“停住时是否在转舵”时，使用：

```bash
/usr/bin/python3 tools/record_navigation.py --domain-id 216 --seer-ip 192.168.192.5
```

这会在独立线程、独立连接上以 5 Hz 查询状态端口 19204 的 API1005，单次连接/请求期限 0.3 秒，失败后退避重连。不访问控制端口，不发送速度、任务或恢复指令。可用 `--steering-rate-hz` 设置 0.5～10 Hz。

新增 `steering.jsonl` 保存完整返回和主机请求/接收时刻，`steering.csv` 保存轮角及速度列，summary.json 的 steering 字段显示成功数、错误数、延迟和最新轮角。

- `steer_angles`：接口资料定义为当前多舵轮角度，弧度，按控制器模型顺序；未独立确认时不擅自命名为前/后。
- `r_steer_angles`：接口资料定义为收到的舵角指令，原数组保留；当前实测可能只有一项，不能假定与两只实际角逐项对应。
- `motor_steer_angles`：保留名称和值的原始结构；不擅自将未核对字段标为实际角或为缺失轮补目标值。
- 同时记录 vx/vy/w、r_vx/r_vy/r_w、is_stop，均为 API 原始参考坐标；与 ROS 指令比较时需考虑参考轴变换。

主机记录时刻用于对齐观察，create_on 仍只作为 API 上传时间保存，不冒充测量时间，也不因此确认数据新鲜度。轮角的正负/零位、两轮模型顺序和允许到位误差尚未由这次记录标定。舵轮相差约 180 度可能涉及滚动方向选择，不能仅看绝对角差判定未对准。

2026-11-18 只读试采：6 秒 30 次成功，零错误，最大查询耗时约 5.8 毫秒；两项实际角及一项收到的目标角已记录。内存套接字测试证明仅发送 API1005，另验证断线记录和有界退出；原导航记录器的 4 项回归测试也通过。
