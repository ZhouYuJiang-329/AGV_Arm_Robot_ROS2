# 仙工连续估计里程计

实现及只读实测日期：2026-11-11。软件输出是 **1005 实际速度积分得到的估计里程计**，不是原生轮式里程计；运动精度尚未验收。没有发送运动、DO、重定位、建图或推送配置指令，不启动 AMCL/Nav2，不发布 map→odom，不使用 cmd_vel 或 1004 位姿差分。

## 数据来源核对

依据本地 `docs/agv_docs/seer_api/` 的《查询机器人位置》《查询机器人速度》《查询编码器脉冲值》《坐标系》《查询批量数据1/2/3》《机器人推送》《配置机器人推送端口》和《实时获取3D扫图数据》：

- 1004 是世界定位，loc_method=3 不证明独立连续里程计或重定位不跳变。
- 1005 的 vx/vy 是机器人坐标系实际速度（m/s），w 是逆时针为正的角速度（rad/s）。r_vx/r_vy/r_w 是收到的指令，完全忽略。
- 1018 返回电机脉冲；缺轮径、减速比、分辨率、舵角和运动学标定，不能直接形成可靠里程计。
- 9301 推送沿用批量状态字段；配置 interval 不证明硬件更新率，也没有发现经过验证的连续位姿及采样时间契约。本轮不改变推送配置。
- Message_MapOdo 出现在启动3D建图后的 rawmap 日志下载流程，1780/1800 不是正常运行的实时里程计流。
- 1005 没有已验证的采样时间，create_on 明确是 API 上传时间。实机返回字段也未给出可靠采样编号。无法判断两次相同速度是否来自同一次设备采样；不会因静止速度相同而去重。

没有足够证据证明原生实时接口可用，故选择1005。它在重定位时的反馈连续性和实际反馈产生机制仍需运动实测；本实现不读取或用世界位姿覆盖累计位置。

## 参考点转换：启动前必须核对

仙工资料确认机器人右手坐标系、逆时针为正；差动车原点为轮轴中心。当前底盘可能为全向车型，文档图片和 CAD 的 base_link 不足以证明实机原点/轴向一致。必须对照控制器模型和底盘机械基准测量，确认 +X 前、+Y 左、+Z 上和参考点。

配置中的 `base_x_in_seer`、`base_y_in_seer` 是 **base_link 原点在仙工机器人坐标系中的位置（m）**；`base_yaw_in_seer` 是 base_link 轴相对仙工轴的逆时针角（rad）。不支持非平面安装。设 r=(x,y)，先算 v_at_base=(vx-w*y, vy+w*x)，再以 R(-yaw) 旋转到 base_link。yaw角速度保持不变。平移偏置只改变速度参考点；每次会话 odom 初始位姿定义为 base_link=(0,0,0)。

默认 `base_transform_confirmed=false` 会在创建连接前拒绝启动。测量并填好参数后才改为 true；不能把默认零偏置视作标定结果。

## 时间、积分与断线

收到完整有效响应后依次记录 steady_clock 和 ROS now。使用 steady 接收间隔近似测量间隔，假设端点速度近似对应接收时刻，取两端速度平均，在区间内按恒定体速度做 SE(2) 指数积分；用 sinc 小角展开处理 w≈0，保留横移，yaw以 remainder 归一到±π。不积分首次有效反馈以前的时间。

pose 是累计到本次接收时刻的估计值，twist 是本次响应反馈转换到 base_link 的值。消息和TF直接共用同一ROS时间戳、位姿和单位四元数，不转换 steady 的纪元数值到 ROS 时间。网络延迟、缓存、采样异步带来未知时间偏差，端点平均不能消除此误差。

- `max_integration_interval_sec=0.6`，`stale_timeout_sec=1.0`，实际积分上限取两者较小值。默认请求5Hz，仅为目标；应按现场有效响应率调整。
- 查询失败、非法值、超长接收间隔、单调时间回退：丢弃未知区间，保留已有位姿，新有效反馈只建立基准。
- 请求耗时达到陈旧阈值的响应不发布、不积分。设备内部真实采样年龄未知，此检查不能保证控制器没有返回缓存。
- ROS时间为零、停止或回退时，不发布本次消息/TF并废弃积分基准；时间恢复后先建立基准，不跨该区间积分。
- 断线不代表零速度，旧数据不定时重发、不刷新时间戳。诊断用 steady 时间持续报告陈旧。
- 不可恢复丢失时段位移，恢复后保留累计位置并永久标记本会话质量下降；这只保证数值连续，不保证位置仍正确。
- 节点重启创建新 odom 会话，原点与统计重置。本轮不持久化。消费者必须协调重启，不能拼接为同一连续轨迹。

网络操作只在唯一采集线程，至多一个请求在途；慢查询跳过错过的周期，无补发队列。独立状态连接不占运动事务锁，但控制器/网络资源仍共享。连接上限1秒，请求超时1..1000ms；错误后关闭独立连接，0.5~5秒可唤醒退避；退出通知并join，网络等待最长受当前1秒操作约束（另加调度/解析时间）。连接成功后若正在退出不会再发请求。有效响应后恢复初始退避。

## 协方差与诊断

配置初始 x/y 方差0.01m²、yaw方差0.01rad²；速度方差0.0025(m/s)²及0.0025(rad/s)²，对应暂定0.05m/s、0.05rad/s标准差。它们是保守工程初值，**未经运动标定**。方差按标准差上界线性累计（允许持续相关偏差），位置另加入角度不确定性与速度大小的耦合；此为对角近似，不是滤波器估计的完整协方差。缺口给平面位置和yaw方差分别额外增加可配置的 `gap_variance=100`，不会在重连后缩小；该数值是降级标志，不能量化未知运动。

z/roll/pitch 的pose和twist对角方差为1e6，表明未观测；不是精确的三维约束。实机标定后应调整速度误差和初始方差，再验证融合器对二维未观测维度的配置。twist方差参数针对转换后的 base_link，偏移较大时需要把角速度误差导致的线速度误差计入参数。

`/diagnostics` 每250ms发布：累计有效响应率 valid_response_hz、最近请求延迟request_ms、最近有效响应年龄response_age_sec、积分间隔、跳过次数、重连次数、错误数、数据源、时间模式、质量降级。设备真实采样年龄和唯一新样本频率明确标为unknown。响应年龄不是设备采样年龄。正常估计输出也为WARN（接收时间近似），陈旧/错误为ERROR；频率为累计接收统计，不宣称硬件采样频率。

## 构建和运行

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select robot_move lidar agv_bringup \
  --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
source install/setup.bash
cp src/robot_move/config/seer_odometry.yaml /tmp/seer_odometry.yaml
# 编辑 /tmp/seer_odometry.yaml：填写实测偏移及轴向，确认后设置 base_transform_confirmed: true
ros2 launch robot_move seer_odometry.launch.py \
  connection:=实际控制器IP params_file:=/tmp/seer_odometry.yaml
```

启动前检查 `ros2 topic info /odom --verbose`、`ros2 topic info /tf --verbose` 和现有TF链。当前仓库实机 ros2_control 是关节轨迹控制器，未配置底盘里程计；现有实机代码未找到odom→base_link发布。仿真 Gazebo odometry 插件经 bridge 会发布此TF，不能同时作为所有者。运行时发现其他同边TF所有者时应关闭其发布，或指定 `publish_tf:=false` 只保留本节点 /odom（还要避免同名 /odom 多源混合）。关闭本节点TF时，另一所有者负责一致的变换。TF是多边共用话题，仅数 `/tf` 发布者数量不能证明同一边是否重复；应检查发布者和实际变换内容。启动不自动强停其他节点。

```bash
ros2 topic echo /odom --once
ros2 topic hz /odom
ros2 topic echo /diagnostics --once
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_tools view_frames
```

整机入口为 `ros2 launch agv_bringup agv.launch.xml chassis_ip:=实际IP enable_odometry:=true odometry_params_file:=/tmp/seer_odometry.yaml`，还支持 `odometry_publish_tf:=false`。整机会启动原有机械臂/底盘初始化流程，**不是只读验收命令**；只读采集应使用独立launch或探针。`enable_odometry` 默认false，原启动方式兼容。参数均启动时读取且只读，实机 use_sim_time=false。不启动定位或导航。

## RViz 实时查看

在完成参考点确认的参数文件基础上，独立启动采集与RViz：

```bash
ros2 launch robot_move seer_odometry.launch.py \
  connection:=实际控制器IP params_file:=/tmp/seer_odometry.yaml rviz:=true
```

若里程计节点已启动，只开查看器，避免重复启动采集/TF发布者：

```bash
ros2 run rviz2 rviz2 -d "$(ros2 pkg prefix --share robot_move)/config/seer_odometry.rviz"
```

配置固定坐标系为 `odom`，网格每格0.25m；红色箭头保留最近500个经过位移/转角阈值筛选的位姿，箭头方向表示机器人朝向而非速度方向。当前 `base_link` 以红X、绿Y、蓝Z坐标轴显示，不依赖整机URDF或机械臂节点。前进/横移时检查轨迹方向，原地转动时观察当前坐标轴和箭头朝向。静止时轨迹不增长是正常现象，不代表没有反馈。需要清空历史显示时按RViz的Reset；这不会重置节点累计里程计。

当前坐标轴需要 `odom→base_link` TF；若只出现历史箭头、当前坐标轴报错，检查TF所有者及 `publish_tf`。无 `odom` 数据时Fixed Frame报错属于等待数据。首次启动的位置为本会话原点；不要把Fixed Frame改成base_link来测相对地面的运动。

RViz箭头长度固定，不能据箭头长度读取速度。速度数值另用 `ros2 topic echo /odom --field twist.twist` 查看。网格可以直观估量距离，但RViz展示的轨迹仍来自同一里程计，不能替代卷尺或独立角度真值。协方差显示默认关闭，可在Odometry显示下手动启用，查看断线后的不确定性增长。

### 当前机器人坐标关系确认（2026-11-11）

该入口用现有 `agv.xacro` 的纯几何模型发布描述和零位关节，在odom固定坐标系中显示模型、0.25m网格、当前坐标轴及历史位姿箭头。模型通过实际 `odom→base_link` TF整体运动，不生成仿真里程计，不加载ros2_control、不连接硬件或发送控制指令。机械臂、升降等关节是零位预览，不表示实机当前关节姿态。使用本入口时不要同时启动整机的robot_state_publisher或其他发布相同关节TF的节点；实际整机已发布模型时应使用其描述/关节状态，在现有RViz添加RobotModel即可。

模型朝向/位置反映估计里程计，可用于观察平移方向、转向、运动连续性。建议手动低速前进、后退、左右横移及正反转动，检查模型与实车动作一致；红X、绿Y表示CAD的base_link轴，当前用户确认该轴相对仙工轴旋转+90°，不能将红箭头直接认定为物理车头。网格与轨迹都位于odom，不是独立测量基准。RViz Reset只清显示历史，绝不重置正在运行的里程计会话。
