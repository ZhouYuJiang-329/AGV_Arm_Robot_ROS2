## 有效测量射线漏清：复现和修复

在静态地图空白处，旧占据栅格中心约为 map `(4.017, 0.755)`，索引 `(684,149)`。后雷达后续持续返回约 5.215m 的有效远处回波，旧点距传感器约 2.15m，处于清除范围内。整数栅格端点之间的 Bresenham 射线会偏离原始世界坐标射线，漏过该栅格。

新增 `agv_bringup::MeasuredRayObstacleLayer`，继承 Jazzy 的 `ObstacleLayer`，复用原有观测缓存、障碍标记与图层合成，仅替换自由空间射线遍历。用原始世界坐标射线进行 DDA 栅格遍历，保持量程限制，排除实际命中点及其后方；不清除仅在角点接触的侧邻栅格。只有原始时间戳在 0.6s 内、坐标系正确的有限有效回波可清除；未知、空数据、NaN、Inf、过期和未来时间戳均不用于清除。没有添加按时间遗忘障碍的机制。

真实观测转换成独立离线测试夹具，在同一 2cm 栅格、传感器亚栅格位置和射线角度下，原始 Nav2 图层测试得到旧点 cost=254，替换后得到 cost=0。回归同时检查实际命中点、未观测邻点、最大量程、正反方向、水平/垂直/对角和地图边界。

源码：`src/agv_bringup/{include/agv_bringup/measured_ray_obstacle_layer.hpp,src/measured_ray_obstacle_layer.cpp,agv_costmap_plugins.xml}`；实机 YAML 的全局/局部障碍图层均选择该插件。仿真配置不改。测试位于 `test/costmap_clearing_test.cpp`；构建与插件安装在包 CMake/package.xml 中接入。

## 追加：仙工接口和关闭抽样实测

本轮重新从控制器只读查询 `1009`、`1101`、`1400`、`1500` 和 `1019`，并核对本地保存的官方接口说明。当前没有运行 ROS 导航/雷达进程，因此本轮是直接 TCP 接口验证，没有延续上轮 RViz 进程，也没有启动车辆执行链。

- `1009` 文档公开的请求选项为 `return_beams3D`；实机开启后增加的三维设备条目没有 `beams`，并未补全二维束的距离。
- `1101(return_laser=true)` 返回相同类别的二维雷达数据，同样有缺少 `dist/valid` 的束；换批量接口不能解决这个缺口。
- `1400` 确认 `NetProtocol.LaserSample=true`，参数描述明确为 TCP API 的 0.5° 抽样；未找到逐束“无回波原因”或“保证空闲距离”参数。`MultiLaser.LaserFilter=false` 不能证明雷达内部没有过滤，也不能证明无效束为空闲。
- `1500` 核对启用设备为 `laser_front` / `laser_back`，驱动品牌枚举 `FocueRay-h100-TCP`。这是设备配置，不是对未知束空闲含义的证明。
- `1019` 的 `user_objects=[]` 只表示该接口没有列出用户障碍物，不提供所有扫描方向的自由空间证据。

经用户明确授权，做了一次临时参数 A/B：先检查实际 vx/vy/w 均为 0、task_status=0；API 4100 临时设置 `{"NetProtocol":{"LaserSample":false}}`，查询 8 帧后在 finally 恢复原值 true，并分别读回核验。未调用运动、重定位、抢控制权 API，也未使用永久参数写入。

进一步查阅富锐[官方下载页](https://free-optics.cn/DownLoads-cn.php)和公开 ROS2 驱动源码参考（仓库提交 `de6f1e7864ef489098477788477491628fecb850`）：[发布扫描代码](https://git.simanc.com/agv_slam/free_lidar/src/de6f1e7864ef489098477788477491628fecb850/src/rosnode/free_lidar_node.cpp)将零距离转为 Inf，而[滤波实现](https://git.simanc.com/agv_slam/free_lidar/src/de6f1e7864ef489098477788477491628fecb850/src/driver/trailing_filter.cpp)也会将过滤点写为零。这是另一个不能直接照搬 Inf 清除的理由；它不是本机仙工固件内部实现的证明。没有连接占用原生雷达 TCP 会话，没有启动会修改频率、分辨率的原生驱动。

**仍未解决的关键缺口：** 在已核对的文档与本机响应中，没有找到能把 `dist/valid` 缺省区分为“超量程无回波”“近距离无效”“被过滤/屏蔽”等原因的字段，也没有找到每束保证空闲距离。有效测距清除已有修复，但缺失测距这一类还不能安全自动清空，问题尚未全部解决。

需要向仙工/富锐确认的具体问题：

1. 此固件 1009 中 `dist` 和 `valid` 同时省略的完整定义，是否只是省略零/false，能否区分无回波与无效/过滤？
2. 是否有公开的原始逐束状态、返回码或“已确认自由距离”接口，及其适用固件版本？
3. 如果只能使用原生雷达协议，是否支持与仙工连接并行的只读数据会话，哪些状态可以明确用于自由空间清除？

拿到明确语义或额外有效观测后才能补上相应适配。现有接口无点、`valid=false`、返回零、用户障碍物列表为空或画面空白，均不足以自行宣布无遮挡。自动清图、按时间遗忘、将未知改为最大量程并不是这类缺口的修复。

- [ ] 只对明确识别的超量程无回波束设计有界清除，清除距离受代价地图射线范围约束（当前配置 4.0m）；不把缺字段、NaN、任意零距离或 `valid=false` 一律变成最大量程/Inf。
