# 仙工雷达采集接入实施计划

创建日期：2026-11-05。

状态：阶段 0～4 的软件实现和自动测试已完成，阶段 6 的可选启动接入已完成；阶段 5 的实机数据/几何验收及 TF 标定待完成。实现日期：2026-11-05。未自动提交 Git。

## 1. 目标与范围

新增独立的 ROS2 `lidar` 包，通过仙工 TCP API `1009` 采集前后雷达，分别发布标准 LaserScan，统一管理采集线程、连接恢复、数据新鲜度和设备状态。

完成后的交付行为：

- 一个节点、一个采集线程、一个独立状态连接，一次查询获取多个雷达。
- 前后雷达分别发布 `/scan_front`、`/scan_back`，使用不同的 ROS 坐标系。
- 无效或缺失测量保留为未知数据，不插值制造距离。
- 查询超时、网络断开后能恢复；停止节点时线程和连接正常释放。
- 发布诊断和兼容现有整机的 `radar_heartbeat`。
- 雷达采集不共用底盘运动对象的连接、事务锁或执行线程。

本轮不实现里程计、双雷达融合、AMCL/Nav2 接入、仙工主动推送、原生雷达驱动或通用插件系统。这些能力在基础采集验收后分别推进。

## 3. 架构和代码位置

```text

```

新增采集路径：

```text
LidarNode：参数、采集线程、重连、诊断、发布
```

## 4. 各层契约

### 4.1 Transport：最小扩展

在现有接口旁增加选择通道的连接重载，例如：

```cpp
bool connect(const std::string& ip, const std::vector<ApiChannel>& channels);
```

- 原 `connect(ip)` 保持原四端口连接行为和连接顺序。
- 雷达只请求 `Status`，不要求其他三个端口可用。
- 空通道集合、非法枚举和重复通道的行为必须明确：空/非法拒绝，重复项归并一次。
- 所选通道任一失败时清理本轮全部连接；连接/重连期间不得并发执行 request。
- 保留完整收发、序号和响应编号匹配、4 MiB 限制、压缩拒绝、事务超时和失败清理。
- 不为同一 Transport 增加复杂的并发请求机制，运动和雷达由不同实例隔离。

### 4.2 LidarSource：同步读取接口

接口提供 `connect()`、`readBatch(deadline)`、`disconnect()` 和虚析构。配置由实现构造时接收；不把 ROS 参数或 ROS 消息传入数据源。

`readBatch()` 返回明确的结果类型，区分成功、超时、连接失败、协议/JSON 错误、API 错误。成功携带一批设备扫描；空 lasers 或缺少已配置设备由节点分别诊断，不能混为 TCP 断线。

`lidar_types.hpp` 定义：

- `Beam`：可选 angle/dist/rssi/valid，以及虚拟点标记；角度在解析层统一转 rad。
- `DeviceScan`：设备名称/编号、波束、量程、标称频率、源时间戳、安装信息。
- `ScanBatch`：多个 DeviceScan、本次请求起止的本机单调时间、接收时刻的 ROS 时间由节点另行记录。
- `ReadResult`：状态、简短错误说明、成功时的数据。

原始源时间戳使用足够宽的整数保存，字符串严格解析，不先转 double。缺省与合法零值分别表达。结构有效性与逐点有效性分别判断，不因少量坏点丢弃整个设备扫描。

SeerLidarSource 内部持有独立 Transport，零正文调用 1009，校验完整 JSON、ret_code 和设备字段。非法 JSON 使连接失效；完整 API 错误保留明确的业务错误语义。整个请求沿用一个绝对截止时间。

### 4.3 LaserScanBuilder：扫描转换

转换函数无网络、无线程，不读取 ROS 参数。可以使用 LaserScan 作为输出，但输入是类型化数据和明确的设备转换配置。

- 按每点实际 angle 投到配置的固定角度栅格，不用原数组下标推算角度。
- 栅格起止角和分辨率按设备配置，启动时验证有限性、正增量和最大格子数；不直接相信元数据 min_angle 与数组一一对应。
- 所有距离先初始化为 NaN；角度/距离缺失、valid 不为 true、非有限值、量程外或虚拟点均不生成有效测量。
- 有效零角必须保留。缺失角度不能自动补零。
- 同格冲突取最近有效距离，强度与该距离来自同一个测量；强度数组按明确策略处理缺值并与距离长度一致，或整帧不提供强度。
- 不做距离插值，不将未知数据直接改为正无穷或最大量程。
- 超出输出角域的点统计并报告；不能用夹紧序号把它们投到边缘格子。
- 输出满足 `angle_max = angle_min + (N-1)*angle_increment`。
- 首版只表达一帧角度重采样结果，不宣称去畸变；逐束时间未知时 time_increment=0，文档说明限制。

### 4.4 LidarNode：所有采集生命周期的唯一管理者

- 持有一个 LidarSource、一个可 join 工作线程和明确的停止信号。
- 工作线程独占 connect/read/disconnect 操作。ROS 定时器不执行阻塞网络读取。
- 线程根据目标请求周期发起读取，同时至多一个请求；慢查询跳过错过的周期，不排队追赶。
- 成功后分别更新设备状态、构造并发布新扫描；不增加无限队列或独立发布线程。
- 诊断定时器只读取短锁保护的状态快照，不持锁等待网络或发布。
- 失败后关闭失效连接，按可中断退避等待后重连。初始建议 0.5 s，倍增至 5 s；正常有效响应后恢复初始值。
- 明确区分 Connecting、Running、Backoff、Stopping；连接成功不代表所有雷达都有数据。
- 退出先通知停止并唤醒等待，再回收工作线程、关闭资源。连接和请求必须有上限，不能 detach 或依赖无限 recv。
- 同设备去重按源时间戳执行；两台设备独立，不要求一次响应中的两帧同步。
- 旧时间戳不能刷新新鲜度。设备时间回退时清理本次设备时间会话并发出诊断；接收时间模式可在新会话继续，不能静默复用旧时钟映射。

## 5. ROS 接口、配置和时间

| 配置/接口 | 首版约定 |
| --- | --- |
| connection | 启动时传入控制器地址，不硬编码现场 IP |
| request_rate_hz | 默认 5.0，是请求目标频率，不是设备扫描频率 |
| request_timeout_ms | 默认 1000，验证正数且不超过当前 Transport 的事务上限 |
| devices | 按 device_name 映射 enabled、topic、frame_id、输出角域和分辨率 |
| 雷达话题 | 默认 /scan_front、/scan_back，sensor_msgs/msg/LaserScan |
| 雷达坐标系 | laser_front_link、laser_back_link，拒绝重复 frame/topic 配置 |
| 数据 QoS | 使用 ROS2 传感器数据 QoS，有限深度，避免积压旧帧 |
| /diagnostics | 每设备在线/新鲜度/有效点数，查询延迟、实际帧率、错误与重连次数 |
| radar_heartbeat | std_msgs/msg/Header，兼容现有 agv_bridge |
| use_sim_time | 实机默认 false |
| stamp_mode | 首版只启用 receive_time，保留源时间戳用于去重和诊断 |

所有启用设备都具有新鲜的、结构可用的新帧时才更新整机雷达心跳；空启用列表拒绝启动。全部距离无效单独报告，不直接等同于断线。新鲜度使用 steady_clock，并按设备源时间更新，不由诊断定时器自行续期。

发布 header.stamp 使用采集线程记录的本机接收 ROS 时间。该模式含网络延迟，不称为精确采集时间；前后雷达的源帧年龄仍可能不同。source_time 同步模式不在首版伪实现，待确认设备时钟基准和重启行为后再增加。

安装外参由实测 URDF 固定关节或固定 TF 发布器负责，同一变换只有一个发布者。仙工 install_info 只保存/展示核对；yaw 单位、upside 含义、角度是否已经安装补偿需实机确认。未确认前不得只用 yaw 推导倒装 TF，也不得重复变换波束坐标。

首版 launch 独立启动雷达节点，不自动启动现有整机运动流程。后续在 agv_bringup 中以明确开关接入，统一传递地址和 use_sim_time。
