# Nav2 普通零速误锁定修复（2026-11-18）

## 已复现的问题

实车导航目标开始后，保护诊断为 StopRequested: explicit_zero，zero_ack=true、stopped_confirmed=true，门禁随后暂停执行生命周期。再次发目标时，bt_navigator inactive 并拒绝目标。定位、扫描和 TF 当时恢复正常不能解除该锁定。

旧代码对运动后的所有合法零速都调用锁定停止。这与 Nav2 控制器、速度平滑器、碰撞监测器可在正常运行中输出零速的行为不兼容。纯状态机复现非零→零速→新非零时，最后的指令被拒绝；新增回归测试在旧代码上明确失败。

本次确认的是零速被锁定这一状态机原因；原始零速究竟由哪个上游组件产生，没有当时的速度话题记录，不能断言是控制器还是避障组件。修复也不代表此前定位年龄问题已解决。

## 修复行为

- 普通合法零速进入 CommandedStop，清除排队速度，发送一次零速并等待应答；应答前的运动请求直接丢弃，不排队。
- 零速应答后不自动重放速度，仅在输入健康且收到新的有效非零指令时继续。ROS 接收端在普通零速处推进源时间戳屏障，早于该零速的延迟消息不能重新驱动。
- 停车可一直保持，正常到点或取消后的零速不再仅因上游不继续发零速而变成命令断流。停止确认仍依赖持续新鲜的低速反馈，ACK 不能代替实际停车确认。
- CommandedStop 继续受定位、扫描、TF、心跳监督；输入失效仍锁定 Fault。运动中的命令断流仍锁定 StopRequested，通信失败及零速请求失败仍锁定并执行有限次停车重试。
- Fault/StopRequested 不能被后续普通零速或新运动指令清除，仍要求原有显式恢复流程。未接受任何运动前的空闲零速仍不向控制器发 API2010，避免抢占其他任务。
- Python 执行门禁接纳 CommandedStop 并保持心跳，不再为正常零速暂停整个 Nav2；暂停日志增加 guard 诊断、参数检查和扫描新鲜度信息。
