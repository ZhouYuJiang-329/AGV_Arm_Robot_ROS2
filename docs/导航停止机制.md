# 导航停止机制与实机验收

适用于 ROS2 Jazzy / C++17。此功能是应用层运动保护，不是硬件急停或安全认证功能。
软件和模拟测试不证明断网实机停车；当前默认配置拒绝非零运动。

## 当前路径与覆盖范围

| 入口 | 消息/调用链 | 保护范围 |
| --- | --- | --- |
| Nav2 最终输出 `/cmd_vel` | `geometry_msgs/msg/Twist` → `navigation_guard_node` → 独占 `seer::Client::setVelocity` → Transport 控制端口19205/API2010 | 本文状态机、输入检查、超时和有界停车请求 |
| 独立旧 `robot_move_node` | AGV订阅改为 `/legacy_cmd_vel` → `UniversalRobotDriver` → `AGVRobotMove` → Client/API2010 | 仅增加固定800ms duration；没有本文导航状态机，不得与导航驱动并用 |
| `scan_config` / `scan_ctrl` | 旧节点扫查器配置/长任务 | 不由导航watchdog保护，不在导航驱动暴露 |
| `robot_distance_move` / `robot_rotate_move` | Twist → 旧节点任务线程 → AGV/API3055平移、3056旋转，轮询1020 | 独立任务协议，不由速度watchdog保护；退出本地等待也不代表取消机器人任务 |
| 整机WebSocket `chassis.velocity_move` / `agv.move` | `AgvHardwareInterface::handleCommand` → AGV/API2010 | 默认旧模式只有限duration；`navigation_mode=true` 时插件完全不连接、不初始化底盘并拒绝这两条入口 |
| `BridgeManager::publishChassisCmd` | 库函数发布 Twist，现改为 `legacy_cmd_vel` | 当前仓库无调用者；不能作为导航命令源 |
| 第三方客户端、机器人手柄、自带导航任务、直接使用Client/AGV库 | 其他控制协议/控制权所有者 | 不覆盖，不保证可被本机零速抢占 |

非AGV类型的 UniversalRobotDriver 保留原 `/cmd_vel` 入口。不要为真实AGV同时启动其他类型的底盘驱动。
导航驱动本身不执行DO、重定位、抢占控制权、取消导航任务或网络配置操作。
API2010文档明确该请求会取消控制器当前导航任务；即使零速也不能用于未经授权的运行中设备测试。

现有 `agv_navigation.launch.py` 只启动Nav2，不启动任何底盘驱动；默认仿真时间、生命周期不激活。
实际发布链依用户提供的Nav2参数决定：通常 controller/behavior → velocity_smoother → collision_monitor → `/cmd_vel`；
仓库仿真配置中最终 collision_monitor 输出 `cmd_vel`，并显式 `enable_stamped_cmd_vel=false`。
实机参数必须保持 Twist、绝对话题匹配；不能把中间输出再接到底盘。上线时用只读
`ros2 topic info /cmd_vel --verbose` 核对发布者及唯一导航订阅者，禁止旧节点remap回`/cmd_vel`。

## 状态与恢复

- `WaitingForInputs`：未满足启动门禁或缺少必需输入；不缓存非零命令，也不自动发送零速干扰其他任务。
- `Ready`：所有输入健康；仍需收到新的合法非零命令才能进入Active。
- `Active`：合法命令使用steady_clock记录接收时间，仅发送最新待发命令一次，不重发旧目标。
- `StopRequested`：显式零速、命令超时、正常退出；清空待发目标，发零速。应答成功仍只是已请求停止。
- `Fault`：非法命令、Active期间任一输入失效、通信异常、零速失败；锁定运动。

StopRequested和Fault均需显式恢复。恢复要求：启用运动、新鲜度契约已核验、所有必需输入健康、
零速已应答且重试结束、新鲜实际速度在阈值内持续指定时间。
`ros2 service call /navigation_guard/recover std_srvs/srv/Trigger '{}'`
仅清除锁定并进入Ready，不发送速度、不重放历史目标。必须随后发新命令。
零速请求失败后不允许仅凭输入恢复解除锁定；Transport超时可能关闭控制通道，此时需检查网络/控制权后重启驱动。
不自动重连或抢占控制权。初始化连接失败也需检查后重启。

命令QoS为volatile、keep_last(1)。Twist没有header，额外检查DDS source_timestamp：
必须非零、不晚于系统时间、年龄小于cmd_vel_timeout，并晚于最近成功恢复的时间屏障。
缺失、不支持、过旧时间戳按非法命令处理；网络跨主机需同步系统时钟并验证RMW时间戳支持。
非法/超限/NaN/Inf、非平面分量不为零的命令不刷新watchdog，且触发锁定停车。
在StopRequested/Fault中收到的运动命令全部丢弃，不能通过回调队列或恢复服务复活。

## 必需输入与时间语义

所有输入同时受原消息时间戳年龄和本机steady_clock到期时间约束。旧、零、未来时间戳不健康，
不递增的时间戳不刷新。检查时限从原始样本年龄扣除，禁止旧消息在收取时获得完整的新鲜周期。
动态TF直接观察每条配置边的原始header，不以“lookup成功”作为新鲜依据，不接受静态TF冒充动态边。

| 输入 | 默认时限 | 有效条件 |
| --- | --- | --- |
| `/scan_front`、`/scan_back` | 0.6s | 已启用设备均列入required_scan_topics；非空frame、合法量程与角增量、至少一个有限有效量程点、递增且不过期header |
| `/odom` | 0.6s | odom→base_link、有限实际平面速度/位置、单位四元数、x/y/yaw协方差为正且有限（拒绝全零默认质量）、有效递增时间戳 |
| `map->odom`、`odom->base_link`动态TF | 0.8s | 每条边均收到有限平移、单位四元数和新鲜递增时间戳 |
| 仙工定位诊断 | 0.8s | 精确名称、level≤WARN、coordinate_status=configured_confirmed、reloc_status=1、tf_available=true、confidence≥0.5且≤1、有效状态文本；缺字段拒绝 |

定位诊断使用`header.stamp - response_age_sec`还原底层有效观测时间；诊断定时器发消息不能延长底层观测寿命。
默认要求仙工定位。若实际使用AMCL，可把localization_diagnostic设为空，此时定位依赖配置中的map→odom动态TF。
此选择必须与实际架构匹配；其他定位诊断格式不能直接套用仙工字段。AMCL等若未来标记TF，需调整发布端约定，
本驱动严格拒绝未来时间戳。支持通过required_tf_edges配置直接动态边（`parent->child`），不做链路插值和TF发布者仲裁。
不要重复发布同一TF边；另需确保雷达静态安装TF、frame和标定正确。

**当前数据源的已知限制与默认门禁：**

- 仙工1005实际速度无已验证采样时间；现有里程计以新响应接收间隔积分，无法区分控制器缓存的重复速度。
  速度为实际vx/vy/w，不是cmd_vel；但其设备内部采样年龄仍未知。
- 仙工定位1004同样是接收时间近似，无法证明控制器内部缓存pose的新鲜度；已有定位质量/地图/跳变/TF对齐检查保留。
- 雷达1009具备data_nsec。现在拒绝重复与倒退（倒退锁定该设备直到重启）、限制请求延迟，
  并以首帧的设备时间/steady时间为锚检查后续时间推进，拒绝慢放旧帧和异常快进。
  LaserScan采用请求开始时间而非应答完成时间，不掩盖查询延迟；但首帧绝对采样年龄、设备时间单位/语义仍需目标固件核验。
  保留现有radar_heartbeat作为兼容观测，本导航驱动不订阅它，不引入第二套雷达心跳。

因此`input_freshness_contract_verified=false`默认阻止非零运动，也阻止“停止已确认”。
不能仅因话题有消息而打开它。实机必须先核验设备采样时间和缓存策略，必要时更换为带可信采样时间的实际里程计/定位源，
并保证所有中间节点保留原采样时间。此参数是运维声明，不会使不可信数据自动变可信；当前代码没有解决控制器内部缓存检测。
不能确认这些条件时保持门禁关闭，本任务不宣称已经具备完整实机导航条件。

确认停车只使用通过上述新鲜度契约的 `/odom.twist`：线速度合成≤0.01m/s、角速度绝对值≤0.02rad/s，
连续至少0.5s。请求停车时清除此前的低速历史；反馈失效或超过新鲜阈值后重新计时。
无实际反馈、仅有零速应答、或输入契约未核验时均报告`stopped_confirmed=false`。
如果改接合成里程计/指令回显，该确认不成立，不得启用。

## 有限duration与通信边界

仓库文档`agv_docs/seer_api/开环运动_-_Feishu_Docs_6638ef5b0b.md`来源：
https://seer-group.feishu.cn/wiki/S7XvwhwKuinkUqksphgchTbEnie ，本次在线复核无法访问，使用仓库2026-11-02采集文本。
该文本说明API2010的duration单位ms，0=一直保持；缺省使用ControlMotionDuration。
配置项表给出默认500、最小0、最大5000、支持版本`~latest`。
**这只是配置项的范围，不是所有固件API参数有效范围或到期物理制动行为的证明。**
本地保守限制导航duration为1–5000ms，默认800ms；请求字段和模拟应答已离线验证。
仍需目标控制器版本、参数有效范围、刷新时是否重置计时、到期是否归零及减速距离的厂商/实机证据。
诊断始终报告`controller_expiry_stop=UNVERIFIED_ON_TARGET_FIRMWARE`，不提供虚假的“已验证”开关。

建议Nav2最终输出10–20Hz；默认cmd_vel_timeout=500ms，request_timeout_ms=150ms，工作线程检查间隔10ms。
要求duration > timeout + 单次通信时限 + 20ms，默认800 > 500+150+20。
这样正常50–100ms刷新有余量，本机watchdog通常先请求停车，旧目标从不无限重发。
这是参数协调条件，不是实时系统的硬上界；需实测ROS调度/网络尾延迟、控制器减速和指令输出频率。
新命令过密时只保留最新待发目标；慢请求不会形成历史队列。

已有Client和Transport共用absolute steady deadline，包含锁等待、发送、部分读取、应答校验，超时关闭异常通道。
导航worker独占客户端，无长任务、位姿查询或普通任务共享锁；网络收发时不持状态锁，不占ROS执行器。
停车清除待发运动，最多等待一个已开始的普通速度请求（默认150ms）再发送零速；零速最多2次（可配1–3次）。
故障不会创建新连接或无限刷零。正常析构也回收同一线程并请求停车；配置上界约为在途请求+最多N次零速请求+调度开销，
默认约450ms；测试注入的Send实现同样必须遵守deadline。首次连接在spin前执行，四端口各最多1s，失败不重连。
未曾接受运动的进程退出不主动发送零速干扰其他控制者。

控制权依据`agv_docs/seer_api/抢占控制权...md`（API4005）、`查询当前控制权所有者...md`、`释放控制权...md`。
本机制不调用这些写接口，不假设新TCP连接可以抢占控制或中断其他客户端。
TCP已断开时本机零速无法送达。SIGKILL、掉电、崩溃、执行器卡死、网络断开只能依赖控制器有限时长，
而此失效保障**尚未实机验证**。硬件急停与现场监护仍由现有系统承担。

## 配置、构建和启动

```bash
cd /home/zyj/Code/ROS2/AGV_new/AGV_ROS2_Control_Manager
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select agv_bridge robot_move lidar agv_hardware agv_description agv_bringup
source install/setup.bash
# 独立导航驱动：默认双门禁关闭，不进行控制器连接和运动。
ros2 launch robot_move navigation_guard.launch.py connection:=<控制器IP>
# 整机入口：navigation_mode禁用硬件插件底盘直连，由guard独占底盘。
# 此整机入口仍会连接机械臂等现有硬件；不是离线命令，不要在未授权设备上执行。
ros2 launch agv_bringup agv.launch.xml navigation_mode:=true chassis_ip:=<控制器IP> \
  enable_lidar:=true enable_odometry:=true navigation_guard_params:=<已审核绝对路径.yaml>
# Nav2单独启动，实际地图和实机参数自备，先保持生命周期不激活。
ros2 launch agv_bringup agv_navigation.launch.py map:=<地图.yaml> params_file:=<实机Nav2.yaml> \
  use_sim_time:=false autostart:=false
```

整机里程计需先完成现有base_transform_confirmed参数及坐标配置；定位节点需单独使用已审核地图/对齐配置启动，
见`seer_localization_view.launch.py`。整机入口不会伪造定位或自动激活Nav2。
独立与整机二选一启动guard，禁止同时运行旧独立底盘、外部速度客户端或第二个guard。
命名空间会影响相对`cmd_vel`、`odom`话题；显式remap到真实最终输出和实际反馈。

复制`src/robot_move/config/navigation_guard.yaml`到现场配置，不直接打开仓库默认双门禁。
所有参数只读，变更需重启；duration、超时、限速、确认阈值均校验，非法组合在联网前失败。
需要减少雷达数量时，required_scan_topics必须恰好列出实际启用并参与导航的全部雷达。
不允许空雷达列表、空动态TF列表；其他非导航操作使用旧入口，其范围和局限见首表。

诊断`/diagnostics`中`/navigation_guard`包括状态、原因、最近有效命令年龄、每个输入健康/年龄、
零速尝试次数、发送/应答、duration、固件验证状态、运动门禁、确认停车与恢复条件。
这里`zero_sent`表示已发起发送调用，不证明字节已抵达控制器；`zero_ack`才表示API成功应答。
`Fault`、`StopRequested`均不能简写为“已停车”。

## 低速实机验收（未执行，须另外明确授权）

先仅做只读检查：确认控制器型号/固件、ControlMotionDuration支持范围、控制权所有者、
实际速度采样时序和各话题/TF唯一发布者，记录tcpdump或rosbag及诊断。不能由这些查询推断到期已验证。
确认现场无正在执行的用户任务；开环API2010可能取消控制器导航，禁止直接用于未知运行状态机器人。

申请授权时必须列出：具体设备、空旷隔离区域、监护人/硬件急停、测试时长、最大0.05m/s和0.1rad/s、
每项断流/断链方法、恢复步骤及减速/碰撞/失控风险。没有该授权不要打开motion_enabled或执行下列动作。

1. 在可隔离移动/可靠监护条件下验证API2010 duration=800的支持、计时重置、超时实际速度归零、停止距离；
   首次试验不能依赖本待验功能保障安全。记录固件版本、请求及实际速度曲线。
2. 核验输入采样新鲜度契约后才在现场配置打开两个门禁。健康启动但不发布cmd_vel，应无运动；
   10–20Hz低速持续指令不应频繁停顿。显式零速后分别记录请求、应答、实际速度达阈值及确认时间。
3. 停止发布命令，验证本机在timeout后发送零速；恢复发布也不能在显式recover前运动，recover本身不动。
4. 分别中断每个启用雷达、实际odom、定位/动态TF，保持其他命令流，检查Fault、零速及确认；
   恢复输入无新命令仍保持停止。重复/旧数据回放不得刷新有效性；确认无旁路发布者。
5. 在有独立现场停止手段的条件下中断控制链路（需明确是屏蔽19205或断开机器人链路，不能误改永久网络配置），
   验证本机请求失败时报告停止未确认，并用独立实际测量确认控制器是否在有限duration后停下。
   若同一链路的速度反馈也丢失，软件不能确认停车，即使现场观察已停也应维持未确认。
6. 正常SIGINT/SIGTERM退出验证一次有界停车；另行授权后才测试SIGKILL/节点崩溃，验证控制器到期而非析构停车。
7. 每项记录最长停止时间、距离、零速ACK与物理停止差异；任何超出预期立即现场终止，不继续自动重试。

只完成以上目标固件与现场测试，并解决输入内部缓存问题后，才能记录对应边界已验收。

新入口、真实参数、现场审核门禁与本轮结果见[Nav2实机导航接入与验收](Nav2实机导航接入与验收.md)。
该入口使用`/navigation/cmd_vel_guard`作为guard输入，不占用原始`/cmd_vel`。
保护配置新增只读`base_transform_confirmed/base_*_in_seer`，真实发送前执行与odom互逆的参考点/轴向转换；
未确认变换时禁止开启真实运动。`required_static_tf_edges`检查两条雷达挂载，动态与静态TF均按DDS GID检查唯一所有者；

`tf_ownership_valid`与`controller_connected`新增到诊断。仓库运动/新鲜度双门禁及变换确认仍关闭。
